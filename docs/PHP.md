# PHP-скрипты (`public/js/php/`)

⚠️ **Расположение изменилось.** Раньше скрипты лежали в `php/` и `PHPMailer/` в корне проекта и грузились на сервер отдельно, вручную, помимо `dist/`. На хостинге `ai4g.ru` выяснилось, что прокси перед сервером пускает на Apache (где физически лежат файлы сайта) только запросы с префиксами `/img/`, `/js/`, `/css/` — всё остальное, включая `/php/`, уходит на другой бэкенд (Tornado, личный кабинет) и отдаёт его `404`, даже если файл на сервере есть.

Поэтому обе папки перенесены внутрь `public/js/`: `public/js/php/` и `public/js/PHPMailer/`. Vite копирует `public/` в `dist/` как есть, так что теперь PHP-скрипты сами едут вместе со сборкой (`npm run build` → залить `dist/`) — больше не нужно вручную закидывать их отдельно. Фронтенд обращается к ним по `/js/php/...`.

## 🟢 Активно используются

| Файл         | Назначение                                                                                                                                                                     | Вызывается из                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| `.env`       | Настройки для PHPMailer и других скриптов: SMTP-сервер, логин, пароль и т.д. Не коммитится в git (`public/js/php/.env`).                                                       | — (читается через `env.php`)                                         |
| `env.php`    | Загружает переменные из `.env` в `$_ENV`/`putenv()`, чтобы остальные скрипты могли их использовать.                                                                            | Подключается через `require` во всех скриптах, которым нужны секреты |
| `mail.php`   | Обрабатывает форму записи на сессию: reCAPTCHA + honeypot-проверка, отправка письма админу и клиенту через PHPMailer (с fallback SMTP-хостом), POST на `ai4g.ru/autoregister`. | `request-form.html` + `form-validation.js` (POST на `/js/php/mail.php`) |
| `upload.php` | Принимает аудио/видео файл, валидирует расширение/MIME-тип/размер, сохраняет в `uploads/` рядом с собой под случайным именем.                                                  | `allegro.html` + `allegro-page.js` (POST на `/js/php/upload.php`)    |

`mail.php` подключает PHPMailer напрямую из `PHPMailer/PHPMailer.php`, `PHPMailer/SMTP.php`, `PHPMailer/Exception.php` (`require __DIR__ . '/../PHPMailer/...'`). Так как `public/js/php/` и `public/js/PHPMailer/` — соседние папки внутри `public/js/`, этот относительный путь остался рабочим и после переноса.

## 🟡 Используются, но не подключены к текущему фронтенду

Форма оплаты (`partials/payment-form.html`) сейчас постит **напрямую в PayKeeper**, минуя эти скрипты. Оставлены как задел под будущую интеграцию — см. обсуждение ниже.

| Файл                  | Назначение                                                                                                                                                                                              | Кем должен вызываться                                                                                           |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `pay.php`             | Записывает заказ в БД (таблица `transcribator_payments`: `email`, `phone`, `files`, `format`, `price`, `order_id`), затем через PayKeeper API получает токен и создаёт счёт, возвращает ссылку на счёт. | Никем сейчас. Задуман как обработчик оплаты транскрибатора.                                                     |
| `payment_success.php` | Вебхук PayKeeper (server-to-server): проверяет md5-подпись запроса (`id+sum+clientid+orderid+secret`) и помечает `transcribator_payments.paid = true`.                                                  | Сервер PayKeeper — URL уведомления настраивается в личном кабинете PayKeeper, не в коде.                        |
| `payment.php`         | Альтернативный, более старый вариант оплаты — без записи в БД. Принимает `Имя`/`Телефон`, создаёт заказ через PayKeeper `order/inline/`.                                                                | Кнопка «Оплатить», которую рендерит `form_handler.php`.                                                         |
| `form_handler.php`    | CSRF-защищённая форма регистрации (`Имя`/`Телефон`/`email`/`contact`) → данные в сессию → HTML с кнопкой «Оплатить» (action на `payment.php`).                                                          | Никем. Ни одна страница сайта сейчас не постит данные в этот скрипт — нет ни формы, ни генератора `csrf_token`. |
| `download.php`        | Отдаёт файл из `uploads/` рядом с собой по параметру `?file=` как вложение (`readfile`).                                                                                                                | Никем из фронтенда. Предположительно — для ручной раздачи готовых расшифровок.                                  |

## Что решить по «жёлтой» группе

`pay.php` / `payment_success.php` / `payment.php` / `form_handler.php` не участвуют в реальном флоу оплаты. Варианты:

1. **Оставить как есть** — почистить/переименовать упоминания без изменения логики, форма оплаты продолжает работать напрямую через PayKeeper.
2. **Связать `pay.php`/`payment_success.php` с реальной формой оплаты** — переписать `payment-form.html` и JS так, чтобы оплата транскрибатора шла через `pay.php` (запись в БД + создание счёта через API), а не напрямую в PayKeeper. Более крупная правка — делать отдельно от переноса на новый хостинг, не одновременно.
3. **Удалить явно мёртвый код** — `form_handler.php` и `payment.php` (старый неиспользуемый флоу) удалить, `pay.php`/`payment_success.php` оставить как задел под будущую интеграцию.
